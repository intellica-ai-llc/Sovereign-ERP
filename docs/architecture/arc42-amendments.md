# Amendments to apply to arc42 (toward v1.0)

Each item is something this repository's code, specs or measurements showed to differ from, or add to, the arc42 text (v0.8 and the later rounds). Apply them in the arc42 itself; this list is the work order and the evidence trail.

| # | Where | Amendment | Evidence |
|---|---|---|---|
| 1 | Appendix D, TLC configuration | Add `CHECK_DEADLOCK FALSE`. Without it TLC stops with "Deadlock reached" once every transfer id is finished. | TLC 2.19 run; `formal/tla/Ledger.cfg` |
| 2 | Appendix D, `Next` | `Post(i) \/ Void(i)` is indented one column off the outer disjunction list, so TLC evaluates them inside `\E d, c, amt`. The state graph is unchanged, but it explains the 713,185 generated-state figure (each applied 18 times). Re-indent, or state the convention. | `ledger_port` test `generated_state_count_reproduces_tlcs_number_under_its_counting_convention` |
| 3 | Appendix M, Lean | `List.mem_cons_self e t` no longer compiles on current Lean; use `by simp`. The `[checked]` mark should name the Lean version (4.35.0 now). | `formal/lean/ClosedPeriod.lean` |
| 4 | Appendix J | State that the synthetic result does not transfer. On real OFBiz data the Appendix J heuristic, reimplemented, has held-out recall 0.25 (not 0.96) because the "meaningful share of key space" filter discards real relationships; precision 0.53. Inclusion alone: precision 0.12 (confirms the 0.09 finding). | `docs/research/fk-discovery.md`, `cargo xtask bench-fk` |
| 5 | Section 5 (Profiler, Dictionary Reader), Q31 | Replace the heuristic with the two-tier design: dictionary first, then scored inference with provenance and an ambiguous-for-review queue. Measured held-out on `OFBiz`: precision 0.86, recall 0.82; across four corpora leave-one-out mean F1 0.86 (range 0.77 to 0.98); with opaque names about 0.70. Q31 becomes a CI gate (precision and recall at least 0.80, conservative truth) plus a manual transfer benchmark. | eng-0007, eng-0008, eng-0009 |
| 6 | Sections 1 and 6 (Maximo) | Maximo's database declares no foreign keys; relationships are SQL where-clauses in `MAXRELATIONSHIP`, with child columns bare and parent attributes prefixed `:`. The Dictionary Reader should parse them first and report every clause it cannot (OR, subquery, function, grouping, non-equality, null test, system variable). | IBM documentation; `sov-profiler::maximo` |
| 7 | Sections 1 and 11 (risks) | IBM-managed Maximo permits no direct production-database access, even read-only; first input mode must be a restored backup or export, then a reporting replica, then a live read-only connection. Maximo 7.6.x extended support was due to end on 30 September 2026, which makes "profile before you migrate" timely. | eng-0006 |
| 8 | Section 8 (cross-cutting) | Add the verification ledger as a first-class artefact: every correctness claim names the tool and the CI job that checks it (`docs/verification.md`). Two claims recorded as checked in v0.8 failed on re-running (items 1 and 3). | `docs/verification.md` |
| 9 | Appendix C (Definition of Ready) | Spike 3 is split: the dictionary tier needs a real `MAXRELATIONSHIP` export (not available solo; the parser is tested on documented forms only); the inference tier is measured on OFBiz and gated. Spike 1 (Ledger Port) and spike 8 (Period Controller) are met for the in-memory reference model; the TigerBeetle adapter is not. | `docs/verification.md` |
| 10 | Section 9 (ADRs) | Add eng-0005 to eng-0009 (licence format, pilot SKU and first source, dictionary-first discovery, inference method and evaluation) and record that ADR 032 (licensing route) remains open: eng-0005 fixes the licence-key format, not the commercial licensing model. | `docs/adr/` |
| 11 | Appendix J, section 8 | Integer surrogate keys need explicit handling: dense integer sequences include each other by chance (`Album.AlbumId` in `Track.TrackId`). Add the child-is-unique and parent-density evidence and state that one weight set does not fit every schema: choose a named or opaque profile per source from name informativeness (readable-name weights score recall 0.08 on opaque names). | `docs/research/fk-discovery.md`, eng-0009 |
| 12 | Section 10 (quality), Q31 | Record the evaluation protocol with the number: within-corpus held-out modules, leave-one-corpus-out from a neutral start, or opaque names. A first leave-one-out run leaked the held-out corpus through its starting weights; a quoted score without its protocol cannot be trusted. | eng-0009 |
| 13 | Section 5 (Profiler), Section 6 (equivalence replay) | Add a reconciler stage: dictionary links are resolved against data for key direction, cardinality and orphan rows; provenance is recorded per link; a true 1:1 has no direction in the data and needs a stated tie-break (hub tables) or human confirmation. First slice of equivalence replay is a stored-versus-derived balance audit in exact fixed-point arithmetic. | eng-0010; `sov-profiler::reconcile`, `::audit` |
| 14 | Section 1 (goals), Section 3 (context), Section 11 (risks) | Position the first product as target-agnostic migration assurance, with competitors and the ways we could lose recorded (SAP/Palantir/Accenture programmes, data-diff tools, IBM's own upgrade tooling, third-party support firms). Replacement is the later upsell. | `docs/research/competitive-landscape.md` |
| 15 | Section 9, ADR 028 (sync engine) | Decide: own state-based, domain-specific CRDT per aggregate, not a generic third-party engine; work order done (lifecycle register with reopen epochs, immutable add-only entries with voids, write sets with surfaced siblings, conflicts computed from state, Lamport ordering, canonical encoding). Verified by exhaustive reachable-state checks, simulation and TLA+ `SyncMerge`. Each further aggregate (assets, inventory counts, purchase orders) needs its own lattice and verification. | eng-0011; `crates/sov-sync` |
| 16 | Section 9, ADR 029 (mobile shell) | Propose: installable web app first with the core compiled to WebAssembly, native shells later over the same core; accept only after a spike on real devices including a full offline shift and storage eviction. Add tamper-evident field evidence (device-signed, hash-chained entries) and sovereign relay as differentiating features. | eng-0012; `docs/research/mobile-and-connectivity.md` |
| 17 | Section 5 (building blocks), Section 7 (deployment) | Add the evaluation tool as the first deliverable: exported tab-separated files in, deterministic text or JSON report with a SHA-256 digest out, no network, no telemetry, read-only. Live connectors, service and apps follow. | eng-0015; `crates/sov-cli` |
| 18 | Section 8 (cross-cutting), Section 9 | Record the verified-toolchain policy (pinned, bumped only by a change that passes the full gate) and the in-house, hashing-only SHA-256 with its known-answer verification, to be replaced by an audited library when one is approved. | eng-0013, eng-0014 |
| 19 | Section 5 (Intelligence plane P4) | Replace the sketch of \"agents propose, kernel decides\" with the capability, taint-tracking, kernel-dry-run, intent-bound-approval and replayable-audit design, with the six properties listed as tests to write. Not yet built. | `docs/research/agents-and-erp.md` |
