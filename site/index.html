Verify your download

Check every file before you run it. Each release publishes a checksum, a signature and a software bill of materials (SBOM), plus build provenance linking the file to the exact source commit and build.

1. Checksum

sha256sum -c SHA256SUMS --ignore-missing

2. Signature (Sigstore cosign, keyless)

cosign verify-blob \
  --bundle FILE.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/intellica-ai-llc/Sovereign-ERP/\.github/workflows/release\.yml@refs/tags/v.+$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  FILE

3. Build provenance

gh attestation verify FILE --repo intellica-ai-llc/Sovereign-ERP

If any check fails, do not install the file. Contact support and keep the file for analysis. The checksum applies to every build; signature and provenance checks apply once releases are signed (the first evaluation builds may carry the checksum and bill of materials only).

What to include in a request

  • Product version (./sov version) and the digest line at the end of the report you ran.
  • What you expected and what happened, with exact error text and time.
  • The text or JSON report if you are comfortable sharing it. It contains table and column names, counts and a digest, but no row values (the audit report does print key values, so check it first).

Security

Report suspected vulnerabilities privately through the repository’s private vulnerability reporting, or to the security contact in your agreement. See also the security and privacy statement included with every download. Please do not post them in public channels. Never email database credentials or licence files; use the secure channel your pilot contact provides.
